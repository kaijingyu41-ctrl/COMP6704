## 1. What the project does

The project studies the discrete optimal transport (OT) problem, which is a
**linearly constrained convex program**:

```
min_X   <C, X>
s.t.    X 1_n = a        (row / supply marginal constraints)
        X^T 1_m = b      (column / demand marginal constraints)
        X >= 0           (non-negativity)
```

Two first-order methods are **implemented from scratch** and compared:

1. **ADMM** (alternating direction method of multipliers). The marginal
   constraints are handled by an exact closed-form Euclidean projection onto the
   affine set `{X : X1 = a, X^T 1 = b}`, and the non-negativity constraint by a
   second, positive-part block. A residual-balancing variant of the penalty
   parameter `rho` is implemented as well.
2. **PDHG** (primal-dual hybrid gradient / Chambolle-Pock) on the saddle-point
   form of the same program, with step sizes `tau = sigma = eta / sqrt(m+n)` and
   an optional adaptive-restart heuristic.
3. **Pock-Chambolle diagonal preconditioning** for PDHG, implemented and evaluated
   as an ablation (it turns out not to help; the report explains why).

Both are benchmarked against the **HiGHS dual simplex** solver accessed through
`scipy.optimize.linprog`, which is used only as a high-accuracy numerical
reference.

The compared variants are therefore ADMM (fixed `rho`), ADMM with residual
balancing, PDHG, PDHG with restart, and preconditioned PDHG.

Two further pieces are part of the study:

* a **dual-gap certificate** (Proposition 1 of the report). Both ADMM and PDHG
  maintain dual potentials; repairing them to dual feasibility gives an **upper
  bound** on the suboptimality of the returned plan that is computed from the plan
  alone, with no reference value. Because that bound can be small for a plan that is
  merely cheap rather than optimal, a run is called *certified at eps* only when the
  bound **and** the plan's marginal error are both below eps. The same machinery,
  applied to an independently solved dual LP and to a row/column-polished reference
  plan, produces a bracket `[L, U]` on `f*`, together with what it proves about the
  reference value: an upper bound on the reference error where the interval is valid,
  and a *lower* bound on it everywhere (`src/otopt/certification.py`). Validity is
  checked and reported (`polish_reached_precision`, `bracket_is_valid`) rather than
  assumed, so the interval degenerates on the instances where it cannot be trusted.
  The report states plainly which pieces are adopted from the literature and used
  as-is (the splittings, the three enhancements, the regularised baseline) and which
  are this project's own device (the certificate and its two by-products).
* an **entropic (Sinkhorn) baseline** (experiment G), run on the *unregularised*
  metrics over an `eps` grid, so that the price of regularisation is measured
  rather than assumed: it is feasible to machine precision but its entropic bias is
  proportional to `eps` and stays above the tolerance at every strength on the grid.
  A **warm-started decreasing-`eps` continuation** is then run over the *whole*
  `40`-instance grid (every size, both regimes, all five seeds) on the *same* budget
  as a matched fixed-`eps` control, and it settles the obvious objection: the bias is
  set by `eps` rather than intrinsic, since at `eps = 1e-4` `38` of the `40` instances
  meet the two-sided tolerance, at about three times the cost of the LP solvers and
  with continuation roughly `2.3x` faster than a cold start. That is not a reliability
  advantage, though: the tuned ADMM certifies `39` of the same `40` instances at the
  same budget, at about a third of the wall-clock.

## 4. How to reproduce

From the repository root (PowerShell):

```powershell
# 1. install the pinned dependencies
python -m pip install -r requirements.txt

# 2. unit tests: projection, operator adjointness, known optima, KKT certificate
python -m pytest tests -q

# 3. everything: experiments A-G, figures, tables, and the report PDF
./run_all.ps1
```

`run_all.ps1` checks the exit code of every step and stops on the first failure,
so a failed experiment can never be followed by a rebuild of a stale PDF.

Individual steps can be run separately:

```powershell
python experiments/run_experiment_a.py
python experiments/run_experiment_b.py     # scaling and marginal shape (about 15 minutes)
python experiments/run_experiment_c.py
python experiments/run_experiment_d.py
python experiments/run_experiment_e.py     # long-budget checkpoints (about 10 minutes)
python experiments/run_experiment_f.py     # timing repeatability (about 3 minutes)
python experiments/run_experiment_g.py     # entropic baseline + full-grid continuation: the longest step (about 1 hour)
python experiments/make_figures.py
python experiments/make_tables.py
```

Each experiment writes machine-readable raw results to `results/*.json` (not only
pictures), and `make_figures.py` / `make_tables.py` read those files, so figures
and tables can be regenerated without re-running the solvers. Every random seed
and hyper-parameter lives in `src/otopt/config.py`.

## 5. Evaluation protocol

All instances are normalised so that `sum(a) = sum(b) = 1` and the cost matrix is
rescaled to `[0, 1]`. For a candidate non-negative matrix `T` we report

* feasibility error `e_feas(T) = ||T 1 - a||_1 + ||T^T 1 - b||_1`
* objective error  `e_obj(T)  = |<C, T> - f_ref|`

and count a run as *solved at tolerance eps* only when **both** errors are below
`eps` at some logged iterate (diagnostics are recorded every 25 iterations). An
infeasible iterate with a low objective value is never counted as a better
solution. Because every method is run to the full budget and returns its **last**
iterate, a run that is counted as solved can still return a plan whose error is
slightly above `eps`; the worst such case in the study is `e_feas = 1.6e-4` for a
run counted as solved at `1e-4`. Every method receives the same budget (50 000
iterations or 60 s, whichever comes first) and no method stops early on a residual
criterion.

Every run additionally records a **dual-gap certificate**, the right-hand side of
Proposition 1: with the run's dual potentials repaired to dual feasibility, the
quantity `<C - alpha 1' - 1 beta', T> + alpha'(T1 - a) + beta'(T^T 1 - b)` is stored.
It is an **upper** bound on `<C,T> - f*` that never uses `f_ref`, so the accuracy
claims can be checked without trusting the reference solver; it is never read as
evidence that the error is large. It is exactly the primal-dual gap of the pair
`(T, (alpha, beta))`, so it vanishes only when the plan *and* the dual point are both
optimal. Because the bound can be small for a plan that is merely cheap rather than
optimal, a run is counted as *certified at eps* only when this bound **and** the
plan's `e_feas` are both below `eps`.

The same machinery audits the reference solver, and it is deliberately explicit about
what it proves. An independently solved dual LP gives a lower bound `L <= f*`, and
row/column-polishing the reference plan gives an upper bound `U` that is only valid
when the polish reached feasibility *and* the two independently computed endpoints
agree to `ENDPOINT_TOL` (`bracket_is_valid`). Where both hold --- 25 of the 40
synthetic instances and all 20 digit instances --- `f_ref` lies inside the interval,
so its width *is* an upper bound on the reference error, at most `2.9e-9`. Everywhere
else the interval degenerates (`U` can fall below `L`) and the only surviving statement is
the **one-sided** `|f_ref - f*| >= max(0, L - f_ref)` --- the positive part matters,
because a reference value *above* `L` proves nothing at all (the two can legitimately
coincide, so the distance to `L` is not an error). That statement is informative on 14 of
the 40 synthetic instances, where the HiGHS value is below `L` by more than the
floating-point tolerance, by up to `4.6e-8` --- a *lower* bound on the reference error
rather than an upper one. The reference's accuracy is therefore not uniform, and objective
differences below about `1e-7` are not evidence. The audit is numerical, not a certified
interval: its endpoints are checked by residuals rather than with directed rounding.
`make_tables.py` prints these counts, so the numbers quoted in the
report are regenerated from the stored results rather than transcribed.

## 8. Note on scope

This project deliberately contains **no unconstrained optimisation** (no gradient
descent, momentum, Adam, BFGS, ...), because the group presentation of the course
covers that topic. Everything here is about constrained convex programming: each
algorithm exists to handle the marginal and non-negativity constraints.
